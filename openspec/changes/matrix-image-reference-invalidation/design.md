# Design: Matrix 图片引用的可信失效与提交前排除

## Context

动机及上游核查见 [proposal](proposal.md)。本设计跨越事件分发、API 错误分类、引用库与提交准备，且涉及落盘兼容，因此需要独立设计。

现有事实：

- [runtime](../../../src/channels/matrix/matrix-runtime.mjs) 的事件门只接收 message/encryption，解密结果被强制标记为 message；自动关联返回窗口内全部未消费引用，队列准备仅检查 consumed。
- [引用库](../../../src/channels/matrix/matrix-image-inbox.mjs) 的 version 1 采用严格字段白名单、串行写队列、原子替换及写成功后可见；没有撤回状态。相同 room/event 的重复记录不更新、不重排。
- [API 查询](../../../src/channels/matrix/matrix-api.mjs) 将所有 getEvent 错误转成 null；不能凭 null、404 或空内容判断撤回。
- [共享图片装配](../../../src/channels/shared/image-prompt.mjs) 逐张读取和校验，任一错误拒绝整轮；[text bridge](../../../src/channels/shared/text-harness-bridge.mjs) 在媒体类型判断前 await prepareImages。onDelivered 才消费成功引用。
- 现有测试明确约束暂时失败重试、后续排队请求重试图片、已消费图片的精确回复、房间/发送者/线程隔离。不得以全局忽略坏图方式破坏这些契约。
- 2026-11-02 核对 [简化实施证据](../simplify-matrix-scheduled-attachments/implementation-evidence.md)：定时附件简化代码、构建及隔离测试已完成；记录的全量结果为 5,274 通过、0 失败、7 环境跳过，本次规划更新没有重跑。22/24 项完成，6.3/6.4 的目标代码运行加载、全局回答设置启用及读回仍待验收，用户选择暂不启用。
- 简化成果尚未提交：HEAD 仍为 `7a73dd6aaad1155afb1d7e06942c09af4504592d`，新基线是该 HEAD 加现有工作树差异和未跟踪交付物，不是 HEAD 本身。当前入站 runtime、image-inbox、image-input、API、text bridge 和 image-prompt 未出现在简化的 tracked diff 中，入站设计仍适用；后续实施前须重新核对，不能假定工作树不再变化。

## Goals / Non-Goals

**Goals:**

- 将引用的可用性与消费事实分开；只有可信证据才能推进不可逆失效。
- A 处理事件流，B 处理漏收通知后的实际查询；同一请求内排除确认撤回项而非要求用户额外重试一次。
- 失败分类、状态提交、提示与模型提交顺序可用无真实网络的确定性测试验证。

**Non-Goals:**

- 不清理已注入 Session 的历史，不撤销已开始的模型回合，不解决一般文本撤回。
- 不新增群聊回答同步、定时附件发送机制，也不改变其他渠道的图片策略。
- 不推断服务器缺失、桥接编辑或权限拒绝就是撤回，不自动重发提示或模型任务。

## Decisions

### 1. 可信撤回是唯一自动永久失效证据

定义内部结果分类：available、confirmed-redacted、unavailable、cancelled。confirmed-redacted 需要受信 homeserver 返回的合法撤回事件或目标事件上的合法 `unsigned.redacted_because`，且精确绑定当前 room/event；外部 body、引用预览、HTML 或文件名不能提供此证据。

撤回目标同时兼容已核实的 Matrix room-version 形态：旧格式顶层 redacts 与新格式 content.redacts。实现前对照官方规范及 API fixture；两者同时出现且冲突则拒绝作为可信证据，不能任选其一。撤回作者不必等于原图作者，管理员也能合法撤回；以 homeserver 的已接受事件为信任边界。原始加密事件不得凭明文猜测分类；若 crypto 返回真实解密 type，则保留并按支持类型分派。解密只能证明内容由密钥持有者发出，不能证明 homeserver 已授权其撤回目标；解密出的 redaction 仅作提示，须独立读取目标并检查可信的外层 unsigned 撤回证据后才能持久失效。不要假设所有撤回都是加密事件，也不借此次改动扩大可处理事件种类。

事件 ID/发送者不匹配、msgtype 不符但没有撤回标记均为安全拒绝而非永久删除。404 也只代表当前无法取得，不证明撤回。这样 B 的自愈边界是明确证据，而不是猜测任何失败都永久不可用。

替代方案：把全部 event-stage 失败当永久失效最容易解除阻塞，但会吞掉权限恢复或网络恢复后本可读取的图，拒绝采用。

### 2. 保持 getEvent 的默认兼容，给图片读取增加保真查询入口

保留既有上下文查询 getEvent 的 null-on-error 行为，给图片读取增加内部严格查询入口（建议 getEventStrict，复用同一私有 request）；该入口保留 HTTP/Matrix 错误类型和 AbortSignal。runtime 将网络/403/404/5xx/超时映射为 unavailable，可信目标撤回映射为 confirmed-redacted。保持对返回事件 ID、记录发送者及解密结果的校验。

不在底层 API 捕获后伪造已删除，不让普通上下文收集因更改默认抛错行为发生连带回归。新增诊断只能使用枚举及白名单文案，不能外发响应体、下载 URL 或令牌。

### 3. version 2 为独立可用性状态与有界撤回墓碑

v2 文档保留 entries 的原有 consumed 事实，并为每条引用增加 invalidated 布尔状态；失效原因首版仅支持 redacted，不保存整条事件。另存未知目标撤回的最小 tombstones（roomId、eventId），解决撤回先于记录的乱序。墓碑同样按到达顺序、有独立上限（默认复用现有 limit=2000）保留；entries 延续原有全局 limit。对已在 entries 的失效状态不能因墓碑淘汰而复活。

新增幂等 invalidate(roomId,eventId)：同一写队列中同时更新 entry 或创建墓碑，原子落盘后才对外可见；record 检查墓碑，重复 record 不清除 invalidated；markConsumed 不清除 invalidated。pending 排除 consumed 和 invalidated；另提供受同样范围约束的候选状态查询，使“全撤回”仍与“根本没有图片候选”区分，不能仅依赖过滤后的空数组。

v1 读入映射 invalidated=false；第一次实际写入 v2 前保存原始 v1 字节备份（已有备份不能静默覆盖）。无状态变更不强制写盘。严格拒绝损坏、未知字段或未来版本，备份失败或写盘失败拒绝推进。旧程序不认识 v2，降级必须停进程并人工恢复迁移前备份，明确会丢失升级后的消费/失效进展；禁止运行时自动降级。

替代方案：删除 entry 或将 consumed=true 都无需新字段，但删除会丢失显式回复的失效诊断，消费伪装会允许显式回复重新读取，因此不采用。永久无界墓碑保证更强但会无界增长，选有界保留并诚实说明过期重放仍需 B 再次查询。

### 4. Matrix 拥有集合准备，公共图片校验仍然整轮原子

不要让 [共享 prompt 循环](../../../src/channels/shared/image-prompt.mjs) 为所有渠道新增 catch-and-continue。扩展 Matrix 的异步 prepareImages 准备阶段，在实际队列执行时对固定的候选集合重新检查状态、严格读取事件元数据、持久化确认失效项，按原顺序生成有效 sources；元数据可在单请求内缓存，不能跨请求缓存 available 而遮蔽撤回。

准备与读取中的 confirmed-redacted 必须回到同一 Matrix 集合协调路径：更新失效并重新装配本次集合，不把空 Buffer 或 undefined 假装为有效图片。需要的窄扩展是渠道可选的“图片装配完成前重新确认”回调，放在共享语义图片装配到实际 prompt RPC 之间，默认不参与其他渠道。它接收本轮已装配的引用对应关系，排除期间新确认失效的图片并重算图片/总大小及消费清单；不进行第二次模型提交，不重发已发送内容，不无限循环重试。无新图到达时不会扩充固定候选集合。

最终检查必须覆盖本轮重试/重新装配路径和 non-vision 图片转文件路径；被剔除的图不能通过旧的 file source 再进模型。下载沿用共享实际 byte caps、签名、像素/数量等既有校验，预读不允许新增无界下载或绕过 Host 限制。无需为了 B 重复下载整套图片；如重装配，已验证字节只在单请求内有界缓存。

显式回复和图片自身带 @ 不启用“隐式跳过”语义：它们的精确目标若失效必须失败。普通显式回复文本仍不得捞取无关 pending。

替代方案：仅删队首或只取最新一张会破坏多图；失败一次后才失效不能满足同轮 B；全局吞掉 ImagePromptError 会对临时故障产生错误的部分输入，均不采用。

### 5. 提交边界、世代与存储故障必须可解释

候选快照先确定身份，执行时按 store 最新状态筛选，读取后在最终提交准备处再检查一次；在该检查之前已观察到的 invalidation 必须生效。在最终检查与 RPC 的边界外，远端之后才发生的撤回无法追溯取消已提交输入，不提供全局原子撤回承诺。

所有异步读取、状态写入和重新装配均传递现有 signal 并检查 generation。队列准备等待已接收的失效写入 barrier；写入失败必须向当前关联请求传播存储错误，而不是因为旧状态仍可见而错误继续。失败不更新 consumed，也不能将暂时错误持久化为 invalidated。sync 不得在失效状态保存失败后把该撤回无条件判定为已处理并永久越过，需保留可重试的本地处理/游标边界。

不能将墓碑淘汰或 entry 缺失的 `undefined?.consumed !== true` 当作“仍待处理”；执行必须要求引用仍存在且未消费、未失效。重启、重复通知和 markConsumed 与 invalidate 的交错都由 store 串行化维护失效单调性。

读取兜底 B 失败没有可重放的 sync 撤回事件，因此 runtime 需保留仅包含已证实撤回身份的修复集合。后续请求先重试对应 invalidate，再进入不可被 flush 清除的存储安全 barrier；同一目标成功修复后才解除其闭锁，不能清空所有失败来假装恢复。精确回复到达时及自带图片的元数据也不能跨队列永久缓存，实际加载时重新严格查询事件、发送者和真实类型。

### 6. 提示与消费独立，操作提示不依赖回答同步

少量失效项排除后可继续的请求，以 Matrix 既有文字/notice 发送能力最多提示一次：“有 {count} 张已撤回图片未参与本次分析”。这是建议默认 UX，不要求新面板或设置。显式目标失效、全部候选失效、暂时无法读取与存储失败分别使用不同诊断。全部候选仅因前一轮已经成功消费而消失时保持现有队列行为，不误报为撤回。

提示发送失败只记可脱敏的操作诊断，不重试提示、不吞掉有效图片请求；它不能触发 onDelivered 或把图片标为成功消费。成功回答仍仅消费实际提交集合的 event IDs；确认撤回项的失效记录与有效图片后续下载/模型/交付失败彼此独立。新增 t() 中文字面量同步到所有现有翻译字典，当前中文 identity、英文和俄文占位符完全一致。

简化后的“官方独占最终文字”限定为定时回合的模型最终回答，不禁止普通 IM 入站诊断。此处 notice 使用原入站回复目标及既有操作通知路径，不能通过已收窄为 managed artifact 专属的 scheduled 入口发送，也不重新引入文字 manifest、双发送器排除桥或文字兜底。

撤回只影响最终准备边界前的入站引用，不向 artifact registry 或定时 relay 传播“撤销输出”信号。已提交模型输入之后才到达的撤回，不取消对应回合、不关闭其已授权的出站 owner，也不释放其他 Session 的附件；正常取消/失败仍遵循原有 owner 契约。

### 7. 决策记录与已完成简化基线协调

本次只更新图片修复的规划产物，不改简化代码或其产物。实施时再按 write-notes-like-deepseek 将图片生命周期决定记录到 proposed/bug-fix，并在验证完成后同批转 implemented；现有 [非 E2EE 主线记录](../../../.agents/notes/implemented/bug-fix/2026-10-27-matrix-non-e2ee-mainline.md)、[原定时附件记录](../../../.agents/notes/implemented/bug-fix/2026-10-29-matrix-scheduled-artifact-delivery.md) 和 [附件专属简化记录](../../../.agents/notes/implemented/simplification/2026-11-02-matrix-scheduled-attachments-only.md) 为相关但不同决定，需保留后继关系而非重写历史理由。

[定时附件简化](../simplify-matrix-scheduled-attachments/proposal.md)的代码交付是本变更前置基线；其未完成运行验收不是图片修复源码实施的硬依赖，也不是本变更补做的任务。apply 开始时必须记录 HEAD、tracked diff、相关未跟踪交付物和可恢复快照，区分继承的简化差异与本变更新增差异；不要求自动提交，不 reset/checkout 整个文件来覆盖既有成果。

保留官方最终文字、自研附件专属 writer/入口、默认私聊交互枚举及官方文字显式扩域、普通 IM promptRpcId/owner 隔离、旧 Session 附件路由和未知结果不重发。图片修复不新增全局设置写入、运行重载或替简化勾选验收项。

组合回归同时运行入站图片和已完成出站职责分离：普通 @ 排除旧图但只提交一次、notice 不消费图片，定时仅一份官方最终文字和登记附件；已提交后的撤回不撤销输出 owner；其他 Session 入站失败不污染定时附件。覆盖关闭和重启时两套存储各自持久化，不能把入站 invalidated 当作出站 sent/unknown。

### 8. 独立回滚与两套状态版本必须分清

图片引用库是每 bot 的 `matrix-images.json`，当前计划 v1→v2；定时发送库是 `integrations/dsh-matrix/schedule-replies.json`，简化继续保留其既有 v2。这是不同 schema 的两套状态，不能用“保留 v2”一语替代具体恢复方案。

图片修复回滚只能撤销相对简化后基线的自身改动，并在必要时恢复图片库迁移前备份；保持定时发送库原位置、路由和防重高水位，不清空或回退它。回滚 bundle 必须来自包含附件简化、但不包含本图片迁移的组合基线；不能直接恢复旧 HEAD `7a73dd6a` 的整包，或仅恢复其 runtime/controller，导致旧文字发送器/排除桥复活。

如果之后需要同时回滚两项，须另行授权并为代码和两套状态分别制定恢复步骤。本变更不修改简化提案原有历史回滚文字，但明确该旧基线方案不能直接用于两项叠加后的部署。

## Risks / Trade-offs

- [服务器只返回 404 或空内容而没有撤回证明] → 不自动永久失效，保留明确重试错误；这是保守边界而非声称所有不可用引用都能自愈。用户可明确回复新图绕过无关旧候选。
- [墓碑有界淘汰] → 不承诺无限期拒绝任意历史重放；仍在 entries 的失效不复活，读取兜底继续校验。
- [提交准备与新撤回竞态] → 只保证最终准备检查前已观察的撤回；已提交输入不能回收。
- [落盘格式升级使旧版本无法启动] → 首写前备份、严格 v1/v2 读取、明确停机人工恢复步骤。
- [共享准备回调波及非 Matrix 或图片转文件路径] → 默认无回调完全维持原行为，添加其他渠道及 non-vision 回归，禁止通用跳过异常策略。
- [截图中的具体失败形态尚未确认] → 本地可控 fixture 覆盖事件流与查询两种路径；真实互通需要用户另行授权，不在提案阶段读取凭据或发送测试消息。

## Migration Plan

1. apply 前保存简化后工作树的完整安全基线，记录未提交/未跟踪交付物和运行验收边界；后续只叠加本变更，不把恢复旧 HEAD 当清理环境。
2. 在临时状态目录测试图片库 v1 双读、首次写入备份和 v2 原子写，确认重复加载、损坏、未来版本及写盘故障均不丢状态；同时断言定时发送库未被迁移或改写。
3. 实施前完成相关 API/crypto 形态核对及确定性失败回放，记录未验证的真实服务器行为；不把测试桩成功当互通成功。
4. 完成入站与简化后出站组合回归、构建及包校验；这不代表运行中的插件已更新，也不代表简化待办 6.3/6.4 已完成。
5. 部署需另行授权，先停对应写入者并备份图片引用库；加载新 bundle 后读回状态并验证撤回旧图 + 新图 + 普通 @ 的序列。不清空 inbox、不重放旧模型请求，不顺带启用 deliverModelAnswers 或覆盖其他运行设置。
6. 回滚先停止本版本写入，恢复“已包含附件简化但未包含图片修复”的 bundle 与图片库迁移前 v1 备份；保持定时发送库及其高水位、运行设置不变。明确图片备份后消费/失效进展会丢失，可能需用户核对重复分析；只回滚代码而保留新图片 v2 不是安全降级。
