# Agent Note: Matrix 生命周期冗余机制的消融与简化提案

Status: proposed

## Problem

Matrix 非加密主线的实现提交 `1b232261` 为启动、同步、发送和关闭补齐取消与排空约束，但新的生命周期 signal 与部分既有机制重复表达同一件事。仅凭代码行数、重复 await 或现有测试全绿，无法判断哪些机制可以去掉，哪些仍承担失败路径的资源清理。

本提案以 `2ad3f672` 上的消融实验为依据，区分可合并的实现机制与必须保留的可观察行为。实验与候选补丁已完成，正式源码尚未应用这些简化；本文不代表实施授权。

## Proposal

仅在保持原有行为、错误语义和关闭完成条件的前提下，合并以下五处重复机制，不迁移 SDK，不新增配置，不改变 E2EE 默认值、设备身份或密钥存储。

| 简化对象 | 删除重复实现的理由 | 必须保留的条件 |
| --- | --- | --- |
| 控制器关闭时第二次 transition 排空循环 | `close()` 同步关闭操作接收；唯一登记入口 `#withBotTransition` 拒绝后续登记；快照中每个 bot 的最新串行 promise 覆盖所有前序操作，其 finally 在 promise 完成前删除登记。第一次等待后，集合只能已清空，不能再增长。 | 保留第一次 transition 等待，以及晚到 runtime 的 stop 和失败聚合。 |
| `#outboundTasks` 与 `#eventTasks` 两个集合 | 两者没有不同的调度、超时或重试消费者，均由同一生命周期等待完成。 | 合并为一个待完成任务集合，不删除任务登记、失败处理或排空。 |
| 数字 `generation` 计数及沿调用链传参 | 每次启动创建独立 signal，停止会永久中止旧 signal；异步操作与回调捕获自己的 signal，已经能判断所属连接是否失效。 | 保留所有异步恢复点的检查；启动失败清理也检查捕获的 signal；旧 crypto 回调在重启后仍不能写入或回复。 |
| 每个邀请独立的 `AbortController` | 唯一主动取消发生在全局 stop，且晚于父生命周期 signal 的取消；当前不存在单独取消某个邀请的消费者。 | 保留父 signal、每房间超时、邀请去重、在途任务排空与取消后的写入检查。 |
| 紧邻 `#sendOptions()` 的第二次 abort 检查 | helper 已同步检查同一个 signal，紧邻位置没有异步间隔。 | 只移除紧邻检查，不删除加密等 await 之后的检查。 |

实现归属为 [MatrixController](<../../../../src/channels/matrix/matrix-controller.mjs>) 与 [MatrixRuntime](<../../../../src/channels/matrix/matrix-runtime.mjs>)。任务集合的命名应表达统一的在途工作所有权，不为区分任务类别另建框架。

以下行为不属于可删除范围：启动调用必须等到实际启动完成；停止必须取消并排空已接收工作；凭据缺失或读取失败也必须释放旧 runtime；已知加密房间缺少 crypto 时必须在上传前拒绝；事件结果未知不得以新事件补发；同步恢复不得抹掉其他未恢复的业务错误。

## Evidence

2026-10-28 在普通临时副本中执行 19 轮固定面板的消融与恢复对照，没有新增 worktree、分支、依赖或提交。面板包含 Matrix 全套、共享交付、路由、Bridge、reaction、i18n、媒体恢复与消息失败分类。第一阶段各版本均使用 409 项，第二阶段增加一项行为检查后，各版本均使用 410 项；所有完整轮次均无超时、取消或跳过。

- 五项简化分别通过各自相同基线的面板；五项组合通过 **410/410**，副本构建与包校验退出 0。
- 组合源码净少 **10 行、1,832 字节**。收益是减少状态、参数传递与重复维护，不是已证实的性能提升；测试耗时约 25–27 秒不构成性能基准。
- 去掉任务跟踪出现 2 项失败；去掉 initialize 的早期 stop 出现 2 项失败；去掉派发结果未知分类出现 4 项失败；抹掉业务错误、去掉定向失败分类各出现 1 项失败。
- 去掉启动单飞保护时，409 项面板仍通过；新增“第二个调用不得提前成功返回”的检查后，结果为 **409/410**。原有“验证只调用一次”并不足以证明单飞完成语义。
- initialize 早期 stop 的两个反例分别为已有失败 runtime 加上凭据缺失、凭据读取异常。原有缺凭据测试从冷启动开始，未覆盖资源已经存在的情况。
- 加密检查消融先暴露空 crypto 的 TypeError；另加媒体探针实测，保留检查上传 **0 次**，去掉检查上传 **2 次**。最终没有发出房间消息，不等于没有提前上传敏感附件。

五项补充的行为检查目前仅在实验副本中：重启后的旧 crypto 回调；凭据缺失、读取失败时的旧资源释放；同 bot 排队操作与另一 bot 延迟工厂的关闭排空；并发 start 的完成语义。正式实施需要把这些检查纳入 [生命周期测试](<../../../../test/channels/matrix/matrix-lifecycle.test.mjs>) 与 [控制器测试](<../../../../test/channels/matrix/matrix-controller.test.mjs>)。媒体检查需要独立断言上传次数，不能依赖排在前面的错误码断言一定成功。

本地原始日志是忽略目录中的实验产物，不是本笔记的发布依赖。长期保留的依据是这里记录的基线、反例、源码不变量和可重新执行的验收条件，而不是只能在当前机器打开的临时链接。

## Alternatives considered

1. **维持所有现有机制。** 数字代际、分开的任务集合与每房间 controller 让各类状态显式可见，也便于未来引入独立策略。但当前没有消费者需要这些独立区别；同一事实的多个表示增加了参数传递和一致性维护，因此提出上述局部合并，而非继续为未提出的能力保留独立机制。
2. **只凭现有测试全绿判断可删。** 执行便宜、结果直观。但并发 start 的消融在原面板全绿却提前返回；早期 stop 的危险又只有已有资源加凭据失败时才暴露。因此必须结合消费者核查、确定性交错和补充行为检查。
3. **把所有 stop 前提移到调用者，移除私有启动方法里的 stop。** 能避免成功重连路径中的一次空等待。但绑定、初始化和重连需要分别维护停止前提，且凭据失败路径仍需提前 stop；这主要搬迁复杂度，收益不足，不纳入提案。
4. **直接删除任务排空、发送检查与错误分类。** 减少的代码更多。但消融已暴露关闭提前完成、重复投递、提前上传和错误重试建议，破坏保留的用户行为，不采用。

## Acceptance criteria

1. 保留全部现有断言，并纳入上述五项补充检查；基线与简化版本使用相同测试集合，不靠跳过测试、延时假定完成或提高超时预算获得通过。
2. stop/close 等待已接收操作及资源清理；重启后旧 signal 对应的回调不能发布资源、写游标或回复，新连接仍能处理消息。
3. 凭据消失、读取失败、旧 stop 失败与回滚失败均保持当前可见错误及资源保护行为；不能只验证成功替换。
4. 加密不可用时原生发送和附件上传均为零；事件结果未知不发生文件回退或新事务补发，且保留原因与定向公开提示。
5. 完整 Matrix 与受影响共享测试、构建、包校验均通过；生成产物仅由既有构建命令更新，不修改依赖、E2EE 引擎、默认值或用户状态。
6. 获批实施后，将本文转为 implemented，并同步涉及代际实现选择的说明；在此之前不应用实验补丁，不改写原方案为已实施新机制。

## Risks

- 如果以后允许关闭后登记 transition、为任务类别引入不同排空策略，或增加独立取消某个邀请的操作，需要重新评估相应简化，不能把这里的结论当作永久禁止增加状态。
- 用 signal 代替数字代际依赖每次启动创建新 signal，且旧操作捕获旧 signal；若改为执行时读取全局当前 signal，旧任务可能错误地获得新连接的权限。
- 测试通过不是所有网络时序的形式化证明。本实验没有真实 homeserver／Element 互通验证，也不提高现有实验性 E2EE 的安全承诺。
- 行数收益较小；参数和私有签名变更的审阅成本仍然存在。如果实现时必须新增同等规模的替代框架，应放弃相关简化，而不是仅以删除行数为目标。
