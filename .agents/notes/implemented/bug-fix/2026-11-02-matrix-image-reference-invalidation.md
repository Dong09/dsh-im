# Agent Note: Matrix 图片撤回必须终止引用而不是消费重试

Status: implemented

## Problem

群聊图片先进入引用库，后续普通 @ 自动关联未消费项。撤回不传播到引用库时，旧图不可读会使整个提交失败；失败保留待处理图片原本用于暂时故障重试，却让永久失效的引用反复阻塞新图。截图和本地引用状态支持这条缺陷链，但未取真实原始事件，不能声称已证明现场唯一失败分支。

## Decision

以 [OpenSpec 设计](../../../../openspec/changes/matrix-image-reference-invalidation/design.md)为准：可信撤回事件和查询返回的可信撤回标记均写入独立失效状态；404、权限、网络、空内容和解密失败不是永久撤回证据。精确回复目标失效就拒绝，隐式集合在同轮排除确认失效项并提示；其余暂时故障仍整轮拒绝并可重试。

version 2 图片库保留 consumed 和独立 invalidated，以有界墓碑处理乱序；v1 首写前按原字节备份，损坏或未知格式不当空库。入站队列、加载和实际提交前重查，图片和转文件 manifest 同步排除；提示不触发图片消费。已提交之后的撤回不取消模型或输出 artifact owner。

实施基线是包含未提交定时附件简化成果的完整工作树，不是旧 HEAD。图片回滚仅恢复相对该基线的自身变化及图片库备份，不恢复旧最终文字发送器，不触及独立定时库和运行设置。

解密只证明发送者持有密钥，不证明 homeserver 已授权其撤回别人的消息；解密出的 redaction 只能作提示，必须独立查询目标并取得服务器 unsigned 撤回证据后才能失效。队列中的自带图片和历史精确回复也要在实际读取时重新查事件，不能复用到达时快照。已确认撤回但本地写失败的目标保留为修复队列，下一次请求先重试同一失效写入再进入 store barrier，避免安全闭锁变成永久无法恢复。共享最终确认只允许精确 source 身份的有序子集，转文件回退重建清单并排除相同 staged 文件，不以旧 manifest 泄漏已撤回输入。

## Alternatives considered

1. **将查询失败全部标死。** 最容易解除阻塞，但会错误丢弃权限和网络恢复后的图，选仅可信撤回。
2. **删引用或伪装 consumed。** 无需扩展状态，但删除丢精确诊断，consumed 仍允许显式回复；选独立失效和墓碑。
3. **只取最新一张或失败后再让用户重试。** 局部改动少，但分别破坏多图和同轮继续行为，选固定集合的有限排除及提交前复查。
4. **公共图片循环忽略坏图。** 代码容易复用，但会改变其他渠道和暂时故障原子性；选渠道显式启用的集合确认回调。

## Consequences

收益是可信撤回不再让旧引用反复阻塞新图，且精确回复、暂时失败重试、出站 owner 和未知结果规则不被放宽。代价是图片库格式迁移、提交前多次状态检查和有界失败修复集合。

只返回 404/空内容而无撤回证据的服务器仍需用户明确回复新图；有界墓碑不保证无限历史重放；最终检查之后的撤回不能追溯取消已提交输入。两套状态都叫 v2 但 schema 不同，必须独立恢复；旧图片 reader 不兼容新图片格式。回滚图片修复必须保留简化后的附件专属代码和定时库高水位，不能直接整包恢复到旧 HEAD。
