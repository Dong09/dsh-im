# Matrix 非加密主线第一批优化设计

状态：用户于 2026-10-27 批准设计并授权实施；已在隔离 worktree `dsh-im-matrix-mainline`（分支 `matrix/non-e2ee-mainline`）按五任务计划完成实施并通过隔离验证，未提交、未推送、未合并。源码基准：`d9fb1bd8`。

## 目标与范围

用户选择先优化非加密房间的稳定性和维护成本，E2EE 保留为后续研究方向。本批只收敛重复发送策略、连接生命周期和少量重复协议规则；不整体重写 Matrix，不迁移 Matrix SDK，不新增通用控制器框架。

本批保留现有 E2EE 代码、依赖、配置默认值、设备标识和密钥文件，不自动删除、重建或迁移任何用户状态。不宣称现有 E2EE 已获得真实 homeserver 或 Element 互通认证。

## 方案比较

| 方案 | 收益 | 代价 | 本批决定 |
| --- | --- | --- | --- |
| 在现有适配器上局部收敛策略与生命周期 | 可以独立验证发送、连接和状态结果；不改变线程及上下文模型 | 暂时保留部分专用基础设施 | 用户已批准 |
| 同时迁移完整 Matrix SDK | 可能将 HTTP、同步及加密维护交给上游 | 牵涉 Node 持久化、事件模型、设备和打包兼容 | 不纳入本批 |
| 先统一所有渠道的控制器及存储框架 | 可能减少重复管理代码 | 扩大到其他渠道，双凭据与资源清理需要新增扩展点 | 不纳入本批 |

## 一、附件投递只有一个回退所有者

共享 `deliverOutboundArtifacts` 继续拥有图片优先、明确失败后转文件的策略。Matrix 的 `sendImage` 和 `sendFile` 分别只尝试一种消息类型，删除 Matrix 内部图片转文件的第二层重试。

每次成功的原生事件发送均透传服务端 `event_id` 为 `providerMessageIds`。附件、普通文本和主动文本的结果必须通过现有共享回执提取逻辑；不能只返回 `{ sent: true }` 而丢掉已获得的事件标识。流式发送继续使用现有共享 editable stream，不改变用户可见回复形式。

媒体上传失败不等于消息已经发送；事件发送后出现网络断开、超时、成功响应无法解析或缺少有效事件标识时，结果为不确定，Matrix 必须转换为 `artifact-delivery-uncertain` 并保留原因，禁止共享层用新事务标识补发文件。明确的服务端拒绝沿用共享层现有回退策略。API 内部已存在的同事务标识限流重试保持幂等，不把它误删为重复回退。

已识别的加密房间在没有可用 crypto 时必须在发送明文前明确拒绝；附件路径在已知不可发送时不先上传文件。加密引擎可用时仍走原有加密路径，不改变配置模式，不增加明文降级。

## 二、连接、关闭与健康状态一致

Matrix runtime 拥有本次连接的取消信号、启动任务、sync 任务和邀请任务。并发 start 复用同一个启动任务；stop 先停止接收新消息并使本代任务失效，再取消连接任务及已接受的普通 Bridge 工作，等待相关任务结束后才释放 API 和 crypto。不能用两秒 Promise.race 把尚未结束的任务当作已经关闭。

复用共享 Bridge 已有的取消入口。等待收尾期间保留发送及状态持久化依赖，避免回复代码在依赖先被清空后继续运行。取消后的任务不得启动新模型请求或新投递；已经提交到服务端的结果仍按已发送或不确定结果记录，不宣称取消撤回了远端消息。reaction 的在途操作应收到取消信号并纳入可等待的尾任务。

generation 检查必须覆盖启动中资源发布、初始同步和增量批次处理的异步恢复点。旧任务不得在 stop 返回后重新发布 API/crypto、接收新消息或推进同步游标。

瞬时同步失败更新可见连接状态和错误，不继续显示健康；后续成功同步恢复状态。永久认证失败结束当前同步循环，清除 ready；runtime 不再自行安排第二套连接重建定时器，由已存在的共享 supervisor 通过 controller 统一重建。暂态网络失败仍由当前同步循环在可取消的等待后重试。

controller 的 per-bot 串行范围涵盖该 bot 的凭据与配置修改、runtime 切换和删除。close 拒绝新操作并等待已获准的 transition 完成后再销毁资源；异步创建前后都检查关闭状态，禁止排队操作在 close 后启动连接。状态或凭据清理失败必须形成现有返回值可承载的 warning 或明确错误，不得静默吞掉。

状态汇总新增共享 supervisor 要求的 `totals.configured` 和 `totals.connected`，保留现有 `bots/ready/failed` 字段以免产生无关返回字段破坏。顶层 ready 与健康摘要按全部已配置 bot 的实际连接状态计算，不能只比较已经创建的 runtime 数量。

## 三、登录与目标验证共用协议规则

密码登录请求只保留一个实现，由凭据检查与 runtime 启动共同调用；删除无生产消费者的重复 login wrapper 前确认包导出及动态消费者。保留用户 ID、设备 ID、超时、错误分类和 Matrix 身份派生方式，不改变 credential reference 或稳定 botId，不把密码接入擅自改成只能保存 token。

Matrix 用户、事件和房间 ID 的协议判断复用同一组纯函数。主动投递仍保留其自己的目标种类限制，例如只接受真实 room ID 而不是 room alias；不能因为底层校验接受 alias 就扩大主动投递范围。合法 v12 无冒号 room ID 必须可以主动投递，现有合法旧式 ID 继续可用。

## 明确不做

- 不删除或默认停用 E2EE；不移动密钥或更改旧设备身份。
- 不更换 Markdown/HTML 依赖。本批之后再单独评估解析器替换及呈现兼容，避免把新依赖与发送和停机修正混在一起。
- 不调整线程路由、触发规则、可见上下文窗口、消费台账、图片 inbox 和图片关联策略。
- 不删除 `MatrixRoomHistoryStore`，不迁移 SQLite 归档，不更改删除 bot 后历史的保留策略。
- 不改其他渠道的产品行为；共享层如需很小的能力补齐，必须验证已有消费者。
- 不把图谱关系当作运行时正确性的证据，不要求重建图谱或开展全仓重构。

## 验收条件

1. 非加密房间的文本、分段、主动文本、附件和流式发送返回可提取的真实事件 ID；附件回执可以关联机器人事件。
2. 图片明确失败时仅由共享策略转文件；消息提交后超时或响应不可确认时不发送第二条事件。采用固定事务标识的既有 API 限流重试不制造重复。
3. 已识别的加密房间且 crypto 不可用时不发明文、不上传结果附件；crypto 可用的原有路径仍有回归覆盖。
4. 长轮询、登录、初始同步或 crypto 启动挂起期间调用 stop，可通过受控取消和任务交错证明无资源晚发布；stop 返回后无旧代游标写入或新消息处理。
5. controller close 与 bind/reconnect/delete 并发时不会关闭后复活连接；删除的清理失败可以被调用方看到。
6. 暂态失败不会显示全部健康；永久失败不会因陈旧 ready 跳过重建；一个已连接 bot 加一个缺凭据 bot 时顶层不能显示全部就绪。真实 controller 与共享 supervisor 的集成测试验证离线退避，不仅测试二者各自的假对象。
7. 主动目标接受合法 v12 room ID，保持旧式 ID 可用，并拒绝该入口不支持的 alias 或畸形 ID。
8. 线程、引用、上下文消费、图片关联和既有加密专项测试保持通过；不以重写测试来删除保留的产品义务。

## 检查与交付

用受控 Promise、AbortSignal 和桩 API 编写行为回归，不依赖真实时间长等或把 sleep 当同步。先运行直接受影响的 Matrix 测试，涉及共享 Bridge 或 supervisor 时补跑其相关测试；随后执行仓库构建和包校验。报告实际执行的命令与结果，不把本地桩测试描述成真实互通验收。

交付时列出删除的重复策略、修复的可见行为和保留的 E2EE 研究边界；同步更新受影响的当前说明。未准备真实 homeserver/Element 环境时明确标注尚未执行实机验收。

## 留给实施者的选择

局部 helper 的命名、测试文件拆分和小步提交边界由实施者决定。实现不得为本批新增通用插件框架、大量配置开关或新的持久化格式；若实际需要改变上述范围，应先回到设计确认。
